# ИТЭФ / М-20 — v16.1

Лимит команд, часы М-20, UCI и выбор форсированной игры. Рабочий профиль **v11**, глубина **3 полухода**, вариант **«по листингу»**. В этом варианте поведение v16 сохранено, включая счётчики команд и позиций. Оценочные веса, минимакс, границы, номинальные глубины, машинный листинг и команды CPU не менялись. Другие варианты явно меняют допуск ходов форсированной части.

## Запуск игры

На Mac откройте `Запустить.command`. В терминале: `./run.sh`. Нужны Python 3 и компилятор C, как в предыдущей версии. python-chess уже включён; устанавливать пакеты из сети не нужно.

Для позиции Максима после **47…g2** откройте **`Продолжить-партию-6.command`**. Он загружает прилагаемый PGN с полной историей, выбирает чёрные фигуры для игрока и сразу ставит лимит 20 млрд. Перед загрузкой текущее сохранение **в папке v16** автоматически копируется в `game-before-import-…json`; прежняя папка v14 остаётся отдельной.

Чтобы перенести другую незавершённую партию, скопируйте её `game.json` из прежней игровой папки рядом с новым `play.py`, прежде чем запускать v16. В архиве v14 сохранение находится внутри `itef-1966-v12`. Сделайте копию исходного `game.json`. Старые ходы восстановятся, но их показатели времени неизвестны и не выдумываются.

## Лимит и две кнопки

В «Настройках расчёта» доступны **3, 10 и 20 млрд команд**. По умолчанию — 3 млрд, около 41,67 часа М-20, округлённо 42 часа. Изменение лимита не начинает новую партию.

Достижение лимита сохраняет позицию и переводит игру в состояние ожидания:

- **Продолжить счёт** — повторяет расчёт исходной позиции с лимитом 20 млрд на той же глубине. Это новый запуск, а не продолжение памяти остановленного эмулятора.
- **Снизить глубину** — рассчитывает только этот ответ на глубине 2. Обычная глубина партии остаётся 3; отметка о снижении попадает в запись и PGN.

При достижении уже 20 млрд бессмысленный повтор с тем же лимитом не предлагается. Снижение глубины доступно, если текущая глубина выше 2. Пауза сохраняется после закрытия и нового запуска программы: автоматически повторять исчерпанный расчёт она не будет.

Лимит относится к **сумме команд одного ответа**, включая родной повтор с расширенным окном и извлечение хода. Раньше несколько вызовов моста могли каждый получить полный бюджет. Сами инструкции поиска и условия этого повторного поиска не менялись.

## Выбор форсированной игры

Откройте **«Настройки расчёта» → «Форсированная игра»**, выберите вариант и нажмите **«Применить настройки»**. Изменение действует со следующего расчёта, включая ручной повтор после лимита, и сохраняется после перезапуска. Во время счёта настройки заблокированы.

| Вариант | Что допускается в форсированной части |
|---|---|
| По листингу (`listing`) | Прежние правила выбранного профиля без дополнительного фильтра; по умолчанию профиль v11 |
| Узкий: только взятия (`narrow`) | Взятия, удовлетворяющие материальной границе правила (6) отчёта |
| Лимит N шахов на сторону (`checks`) | Широкий допуск, пока соответствующая сторона не исчерпала N шахов; затем для неё только узкий допуск |
| Широкий: все шахи (`wide`) | Шахи без отдельного лимита их числа, взятия и ответы на шах по широкому правилу §4 |

N задаётся целым числом **0–99**, начальное значение поля — **2**. N=0 эквивалентен узкому варианту. Счётчики белых и чёрных независимы, относятся к текущей линии от начала форсированного участка и восстанавливаются при возврате по дереву. Шахи взятиями тоже считаются. После исчерпания N шахующее взятие всё ещё допустимо, если удовлетворяет узкому правилу. Это **не** родной счётчик серии шахов 4777 и не старый профиль v12-narrow.

Альтернативные правила перенесены из проверенного опыта v15. Геометрическая проверка определяет шах по доске; внешняя оценка и сортировка ходов не используются. В узком варианте исключены тихие превращения и тихие ответы на шах. Порядок оставшихся машинных кандидатов сохранён. Общий предел ранга, предварительные фазы, отсечения и селекция у горизонта остаются листинговыми: «все шахи» не означает бесконечную глубину. При сочетании с исследовательским профилем новый выбор имеет приоритет над режимом «только взятия» в форсированном генераторе; прочие параметры профиля сохраняются.

В заголовке PGN: `M20ForcedPlay` = `listing`, `narrow`, `checks` или `wide`; для `checks` добавляется `M20ChecksPerSide`. **Без `M20ForcedPlay` используется `listing`.** Настройки читаются при загрузке PGN; явно указанные параметры командной строки имеют приоритет. Заголовок показывает текущий выбор; фактический вариант каждого рассчитанного хода находится в комментарии `[%m20_forced checks:2]` или аналогичном. Смена вариантов дополнительно отмечается заголовком `M20ForcedPlayHistory`, а разные варианты повторных попыток — в комментарии хода. Старым ходам без измерений не приписывается новый вариант.

Однократные ответы:

```sh
./run.sh --think --moves e2e4 --forced-play narrow
./run.sh --think --moves e2e4 --forced-play checks --checks-per-side 2
./run.sh --think --moves e2e4 --forced-play wide
```

Ваш PGN ИТЭФ — MacHack включён как `examples/itef-machack.pgn`. Загрузить его последнюю позицию: `./run.sh --pgn examples/itef-machack.pgn --side black`. Это замена текущего сохранения с автоматической резервной копией, как у партии 6. В исходном PGN нет пометки варианта, поэтому загрузка выбирает листинг.

## Часы и PGN

В записи каждого нового хода ИТЭФ: число посещённых позиций, команд и оценка времени М-20. Формула: **команды / 1 200 000 = минуты**. До 120 минут включительно выводятся минуты, выше — часы. Это пересчёт при средней скорости 20 000 команд/с, не тактовая модель оригинального компьютера.

Счётчик команд сохраняет определение прежнего моста: поиск и извлечение ответа, без операторской загрузки доски. Основная строка хода показывает его завершённый расчёт. Если ему предшествовало исчерпание лимита, дополнительно указано время с повторами. **Итог партии учитывает и завершённые, и исчерпавшие лимит попытки текущей линии.** При возврате ходов относящиеся к ним измерения убираются вместе с ходами.

В PGN сохранены читаемые комментарии и поля `m20_nodes`, `m20_commands`, `m20_minutes`, `m20_depth`. При снижении — `m20_reduced_from`; при повторе — `m20_total_commands`, `m20_total_minutes`, `m20_retries`. Общие суммы находятся в заголовках `M20TotalCommands`, `M20TotalMinutes`, а сумма только завершённых расчётов — `M20CompletedCommands`. `M20RecordedMoves` показывает число ходов с измерениями.

Ходы человека не получают показатели поиска. У перенесённых старых ходов ИТЭФ отображается «измерений нет». Измерения сохраняются в `game.json` вместе с партией. Если программа сдаётся, её последний расчёт учитывается отдельно в заключительном комментарии и сумме.

## UCI и матчи

Исполняемый файл для GUI: **`uci.sh`**. Равнозначные команды: `./run.sh --uci` или `python3 uci.py`.

Поддержаны `uci`, `isready`, `ucinewgame`, `setoption`, `position startpos moves …`, `position fen … moves …`, `go depth 3`, `quit`. Без указанной глубины используется 3. Позиция с историей передаётся движку полностью. Дефолтный профиль — v11.

UCI-параметры:

| Параметр | По умолчанию | Значения |
|---|---:|---|
| Profile | v11 | v11, v12-source, v12-narrow |
| Depth | 3 | 1–5; 4–5 исследовательские |
| CommandLimitMillions | 3000 | 1–20000; 10000 = 10 млрд, 20000 = 20 млрд |
| ForcedPlay | listing | listing, narrow, checks, wide |
| ChecksPerSide | 2 | 0–99; действует при ForcedPlay=checks |
| PGNFile | пусто | Путь к отдельному PGN текущей UCI-линии; запись включается только при заданном пути |

Пример: `setoption name ForcedPlay value checks`, затем `setoption name ChecksPerSide value 2`. Перед каждым поиском и в итоговом `info string` указан фактический вариант; при снижении глубины он сохраняется.

Для записи заголовков варианта в UCI-матче задайте `setoption name PGNFile value /полный/путь/m20-match.pgn`. Обёртка обновляет этот файл при получении позиции и выдаче ответа, добавляет собственные измерения, выбранный вариант и комментарии к рассчитанным ходам. Это последняя переданная линия с последним выданным ходом; для следующей партии задайте другое имя, если нужно сохранить обе. Родительская папка должна существовать. PGN, создаваемым самой внешней GUI/cutechess, управляет эта GUI; UCI не предоставляет движку команды для изменения её заголовков. Отдельный `PGNFile` обеспечивает запись метаданных независимо от GUI.

При лимите на глубине выше 2 UCI один раз пересчитывает на глубине 2 с тем же лимитом. Перед ответом выводится `info string … fallback depth 2`, а `info depth` содержит фактическую глубину. `info nodes` относится к завершённому расчёту; команды, оценочные минуты и сумма с повтором передаются через `info string`. `info time` — реальные миллисекунды работы компьютера, не время М-20.

Это **обёртка для матчей по глубине**. Для cutechess задавайте `proto=uci`, `depth=3`, `tc=inf`; движком укажите абсолютный путь к `uci.sh`. При необходимости увеличьте допуск ожидания GUI. Управление по обычным шахматным часам и ponder не реализовано. `isready` отвечает и во время счёта. `quit` прекращает дочерний расчёт. `stop` прерывает его без произвольного подставного хода: если завершённого ответа нет, выдаётся `bestmove 0000` с объяснением. Поэтому для нормальных матчей используйте фиксированную глубину без остановки по времени.

Если даже глубина 2 исчерпала бюджет, произошёл останов программы либо она признала поражение, возвращается `bestmove 0000` и соответствующее `info string`. UCI не имеет стандартного отдельного сообщения о сдаче; матчевый скрипт должен различать эти случаи по сообщению.

Совместимость проверена через `chess.engine.SimpleEngine`: рукопожатие, штатный ответ на 1.e4 (1…d5), снижение 3→2, ответ `isready` во время поиска и быстрый `quit`. cutechess непосредственно в этой среде не запускался.

Альтернативные режимы — воспроизводимые исследовательские правила допуска, а не доказанная настройка матчевого экземпляра.
