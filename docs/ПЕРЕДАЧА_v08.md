## 0. Коротко

Цель — довести реконструкцию шахматной программы ИТЭФ для М-20 до партии с Максимом. Стенд: SIMH Вакуленко (github.com/sergev/m20) с нашими патчами, оцифровка `kaissa.m20`, скан 121 листа (`m20-itef.pdf` — Максим прикладывает отдельно).

Сейчас машина сама проходит весь конвейер: распаковка позиции → генерация и регистрация ходов → поиск на глубину 3 с форсированными вариантами (λ = 215 позиций) → минимакс записывает выбор → извлечение → Шлёп → Перевод → ξ1.

**Легального хода ещё нет.** К моменту извлечения корневой список и доска перезаписаны листьями дерева, и ξ1 собирается из чужого слова (§7).

Первое дело — опыт «снимок корня» (§8.1): вероятно, кратчайший путь к первому легальному ходу, выбранному минимаксом самой программы.

Правила раскопа: одно изменение — один замер; приёмка только по числам из прогона; факты отдельно от гипотез; ход объявлять, только декодировав ξ1 по §6.9 и проверив легальность в позиции.

## 6. Карта механики (что понято)

**6.1 Вызовы.** «пв R,SUB,0007» кладёт слово-возврат в 0007; общий выход «→0007»; 0005/0006 — реставратор РА. Параметр подпрограммы = M[возврат−1] (ПУП 2073: 7777+РА ≡ РА−1).

**6.2 Циклы по РА** (пен/пун/пм/пн, 011/031/051/071): если РА ≥ A1 и Ω-условие — переход; РА := A3 (с П=1: РА ± шаг). РА беззнаковый, поэтому «РА ≥ 0» всегда истинно — выход только по Ω.

**6.3 Числа-следы.** Числа в A2-поле пишут командой «ра X,Y,Z» — в порядке остаётся 052 (λ, n и т.п.). Чтение 7776 отдаёт чистое (0,РА,0). При сравнении модулей мусорный порядок следа надо помнить.

**6.4 Регистрация (БУХ 2053–2071).** Клад (1704) = адрес записи; впрыск «шаблон 2025 + клад». Биты растра изолируются x&(x−1) (2061/2062); нормализующее «с» (2063) — декодер «бит→клетка» (нормализация вычитает сдвиг из порядка). Растров f — шесть, 3000–3012 (пометка «{6}», стр. 55).

**6.5 Подготовка (2147).** a_n.A1 := a_{n−1}.A3 («сдма 0130» — сдвиг на 24), клад := a_{n−1}.A3, т.е. список ребёнка идёт сразу за списком родителя. Конец a_n.A3 должен вернуть ПУП (бриф №4); с заглушкой не возвращается.

**6.6 Ход (2205) и откат** (прочтение). Распаковка 2212 с РА = n; «Стоп по λ» (2164) — отладочный останов на позиции №λ с пульта (7771); «Перемотка по λ» (5213→5174) — периодический сброс памяти на барабан («ма/мб»), т.е. **чекпоинт против сбоев машины, а не откат**; «Есть ли шах?» (2173); «Есть ли рокировка?» (2154). Упаковка (2234–2300) пишет 10 слов 6540+РА…6551+РА с П=1. Если РА = n, свёртки уровней перекрываются с шагом 1 — не проверено (§8.2).

**6.7 Минимакс 4100–4106.** Сравнение оценок 7457+РА / 7461+РА; 4105 «пб 6520,4642,7520 П=5»: Λx_n := a_n и переход в Ветку. a_n.A1 к этому моменту уже сдвинут за проверенный ход, поэтому выбранная запись = A1(Λx) − 1 («такт»).

**6.8 Ветка (4630–4644).** Операторский дисплей варианта: «дпб» (037) на 4635/4640 показывают ходы по уровням на пульте и ждут оператора. В БО цикл 4643 «пе 1700,4630,7776» вечен.

**6.9 Формат хода и клетки** — сверено с ходом Опуса и королями:

```
ξ1 (5211), A2-поле = (откуда)(куда) — две восьмеричные пары; собирает Перевод (5162) из 1007 (откуда) и 1006 (куда)
клетка (6 бит) = восьм. цифры (8 − горизонталь)(h − вертикаль):  h=0 g=1 f=2 e=3 d=4 c=5 b=6 a=7
  7150 = 71→50 = g1→h3 (Кh3 у Опуса) ✓     e1 = 73,  e8 = 03
  7655 = b1→c3 (пример формата у rcgoff)    6655 = b2→c3,  0012 = h8→f7
слово короля 3016/7016: клетка = (порядок << 1) | старший бит мантиссы
  «0 35 4000…» = 35·2+1 = 73 = e1;   «0 01 4000…» = 03 = e8;   без бита 4000 король «съезжает» на f1/f8
слово списка: «куда» прямо в поле порядка, напр. «0 46 6402 0035 3740» = на b4
```

**6.10 «Ход из ξ1» (5142)** (прочтение). По ξ1 заново строит корневой список (1465 → 7704/7705), ищет ход с тем же «откуда-куда» (сравнение 5151) и применяет его (распаковка 5155). Так в программу входит ход соперника — основа протокола партии (`docs-prev/OPERATOR_DECK_RU.md`).

**6.11 Внешняя схема и Игра.** 5002 цвет+n; 5004 распаковка (2301); 5011 «Таня»; 5013 → Игра (через 7707). Игра 5220: 1465 «Все возможности» → 5500 ФВ0 → цикл {5226; 5470 «Есть ли Л.Х.?»; 5230 → 4040 Общая схема; 5231 распаковка корня; 5317 «Может хватит?»}. Выход: 5023 извлечение (Λx→1x), 5024 Шлёп, 5025 Перевод, 5026 ξ1 := 0160, 5027 Печать (5112), 5031 Перемотка.

**6.12 Шапка 1353 и вердикт по Гемини.** Таблица (1353 конь→1345/1331, 1354 слон→1226, 1355 ладья→1141, 1356 ферзь→1320, 1357 король→1346/1331, 1360/1361 шах-детекторы) прочитана Гемини верно, лист 19 (стр. 91) сверен глазами. Но это диспетчер по типу: конь первый только потому, что его тип-код 3 минимален (пометка «→конь-3» на шаблоне 1366). Пешки генерируются раньше фигур; гипотеза «Кh3 из-за Шапки» неверна.

**6.13 ПУП (2072–2122)**, что известно. Пролог: РА := адрес возврата; δ₀ (1710) := параметр «п 1663,1704,3545» (ρ | клад | цена); δ₁ (1711) := A3 клада. 2104 — ФК 0030,0000,0000; 2105 «пв 2106,1710,0007» зовёт δ₀ как команду (опыт-1710 подменяет переходом на «цену»). Подозрение: ФК на 2104 должна сформировать в δ₀ команду перехода. 2101–2120 — переупорядочение списка (не разобрано). Выход 2122 — трюк «спа» (§4, №8).

## 7. Где мы — честно

Цепочка механически работает целиком, но легального хода нет.

**7а. Эталон.** Λx₀ = 0 00 6101 0000 6155 → запись 6100. К извлечению зона 6100+ уже чужая:

```
6100: 0 12 4003 0001 3401    6101: 0 21 4003 0001 3401      ← слова чужого уровня (на f7, g6)
6102–6107: на b4 h4 g4 f4 e4 a4   (A2 = 0035; нет c4 и d4 — признак не начальной позиции)
6110–6117: на c3 h3 g3 f3 e3 d3 b3 a3   (A2 = 0034)
6120–6123: на c3 a3 (A2 = 0010, конь b1)   h3 f3 (A2 = 0011, конь g1)
6124+: нули — список 24 слова (корневой — 47)
```

ξ1 = 0012 (h8→f7) собран из слова 6100 (`1006 = 0 12…`, `1007 = 0`, «откуда» не найдено). Корневой список к 5023 не сохраняется; доска тоже не корневая (3016 = 0 12 0000 0001 0000).

**7б. `M20_LEVELS=1`.** Короли теряют младший бит клетки (3016 = `0 35 0000…` → f1 вместо e1), минимакс на корне не пишет Λx₀ (= 0), «такт» берёт индекс −1 → 7777, и Шлёп собирает ξ1 = 6655 из M[7777] и растра 3013 (`1006 = 0 55…`, `1007 = 0 66…`). Это мусор. Совпадение с 7655 (Кb1–c3) в один бит — пока просто совпадение. Опыт сомнителен ещё и потому, что снимок делается на PC=2154 («Есть ли рокировка?»), который в нормальном потоке почти не вызывается.

## 8. План (по приоритету)

**8.1 Опыт «снимок корня»** (без `M20_LEVELS`). Запомнить память при первом приходе на 5230 (после деполза — корневой список готов), вернуть списки, доски и свёртку на 5023 перед извлечением; Λx (7520+) не трогать. Вставить ПЕРЕД блоком «такт» (оба срабатывают на 5023):

```c
		{ /* ОПЫТ-«снимок корня» */
		  static t_value snap[MEMSIZE]; static int have = 0; int a;
		  if (RVK == 05230 && !have) { for (a = 0; a < MEMSIZE; a++) snap[a] = M[a]; have = 1; }
		  if (RVK == 05023 && have) {
			for (a = 06100; a <= 06516; a++) M[a] = snap[a];   /* списки ходов */
			for (a = 03000; a <= 03017; a++) M[a] = snap[a];   /* доска белых */
			for (a = 07000; a <= 07017; a++) M[a] = snap[a];   /* доска чёрных */
			for (a = 06540; a <= 06551; a++) M[a] = snap[a];   /* свёртка корня */
		  }
		}
```

Хак-код в CPU выполняется после проверки точки останова, поэтому снимок на 5230 берётся уже после деполза из сценария. Ожидание: ξ1 декодируется по §6.9 в легальный ход начальной позиции. ## 10. Инструменты

- `tools/dump.py` — дизассемблер оцифровки: `tr -d '\r' < m20/kaissa/kaissa.m20 > /tmp/arc.m20; python3 tools/dump.py /tmp/arc.m20 5000-5036 4100-4106`.
- `M20_WIN_PC=<восьм. PC> M20_WIN_K=<№ попадания> M20_WIN_N=<шагов>` — окно степ-лога: слово, РА, Ω, n, клад, a₀ на каждом шаге.
- `M20_STEPLOG=N` (+ `M20_STEPLOG_FROM=<PC>`) — пошаговый лог с начала / с PC.
- `M20_REG=1` — первые 220 записей в зону списков 6100–7677.
- `M20_TRJ=<PC>` — лента переходов (глючит: логирует только триггерный переход; степ-лога хватает).
- Сторожа в stderr: `[VEC]` — записи в 7700–7717 (в здоровом прогоне 0), `[HB]` — пульс раз в 200 млн команд (в здоровом прогоне 0 строк), `[TAKT]`.
- Сценарий `check-unpack.ini` — проверка распаковки за секунды.

## 11. Ловушки

- `-lm` строго в конце строки сборки; предупреждения scp.c / sim_console.c безвредны.
- Дубль `case` в switch роняет сборку молча — всегда `grep -i error`.
- Барабан: перед каждым прогоном `rm -f /tmp/drum*.dat` (run.sh делает сам).
- go/cont в БО не возвращают управление — только через точки останова или `timeout`.
- Старт с 5001 пропускает распаковку — стартовать с 5002.
- SIMH буферизует stdout: убитый процесс теряет вывод — все сторожа пишут в stderr.
- `pkill -f "m20 final"` убивает собственный шелл — писать `pkill -f "[m]20 final"`.
- `/bin/sh` может оказаться dash: без `TIMEFORMAT` и `time ( … )`, время мерить через `date +%s`.
- «Колода» в рецепте v06 — это стандартные ячейки 0121–0137, не отдельный файл.
- Контейнеры сбрасываются: всё держать в посылке, сохранять часто.
