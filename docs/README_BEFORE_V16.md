# ИТЭФ · М-20 · v12 исследовательская

Добавлены три воспроизводимых профиля поиска и явные настройки форсированной ветви. По умолчанию включён **v11** — прежнее поведение. Исследовательский профиль **v12-source** проверяет символическую запись 4344, предел ранга16 и перенос пяти массивов. Профиль **v12-narrow** включает узкий форсированный генератор взятий, сохраняя штатную защиту от шаха. Исходный машинный листинг, CPU и оценочная функция сохранены.

Запуск доски: `sh run.sh`. Для исследовательского профиля: `sh run.sh --profile v12-source`. Настройки также работают с `--think`; полный перечень — `python3 play.py --help` и [описание профилей](docs/V12_PROFILES_RU.md).

JSON теперь отдельно сообщает `lambda_final_1706` — финальный родной счётчик, и `nodes` — прежнюю сумму счётчиков при повторе поиска. Параметры каждого решения находятся в `search_profile`.

Полный отчёт v12: [счётчики, матрицы и трассы](../v12-analysis/REPORT_RU.md). Проверены 6156 решений, 81 конфигурация. Лучший по λ профиль v12-narrow: медиана 1,595, P10–P90 0,564–4,099, ±10% — 6/73, ходы — 52/73. Критерий исторического принятия не достигнут.

## Справка о v11 и её прежних проверках

Восстановлен правильный переход в поиске ответов на шах. Это исправление исходной v10, а не новая шахматная программа. Машинный листинг по-прежнему выбирает ходы сам.

На первых двух исторических партиях, при восстановлении позиции перед каждым решением и постоянной глубине 3:

| Сборка | Партия 1 | Партия 2 | Всего |
|---|---:|---:|---:|
| v10 | 24/37 | 29/39 | 53/76 — 69,7% |
| v11 | 24/37 | 31/39 | 55/76 — 72,4% |

**Цель 85–90% основного выбора пока не достигнута.** Новых совпадений три, потеряно одно. Первые ответы: за белых `1.e4`, после `1.e4` за чёрных — `1...d5`; исторический первый ответ чёрных `...Nf6` теперь не воспроизводится. Это позиционная сверка, не воспроизведение целых партий без отклонений.

В отдельном диагностическом расчёте двух кандидатур исторический ход присутствует в 64/76 случаях (84,2%). Этот расчёт открывает полное окно, затем повторяет поиск без первого кандидата. Из-за зависимости форсированных ходов от окна его нельзя выдавать за две неизменённые исторические линии или за точность основного выбора.

## Запуск

В папке программы выполните `sh run.sh`. На macOS можно открыть `Запустить.command`. Нужны Python 3.9+ и C-компилятор (`cc`, GCC или Clang). Python-пакеты и доступ в интернет для игры не нужны.

При первом запуске библиотека эмулятора собирается автоматически. Оставьте окно Терминала открытым. На Linux сборка проверена; macOS в этой работе не проверялась. На Windows используйте WSL.

Для переноса партии остановите прежнюю программу и скопируйте только её `game.json` в эту папку. Не копируйте старую библиотеку эмулятора. Новую сборку запускайте из её папки.

На доске доступны глубины 1–3; основной режим — 3. Форсированные продолжения идут за этим горизонтом. Работают отмена хода, автоматическое сохранение и экспорт PGN.

## Что изменено

- Адрес 4231 используется двумя процедурами на страницах 34 и 37 рукописи. В v10 поздняя запись затирала команду установки режима ответа на шах. Ранний хвост перенесён в свободные 4172–4173, оба перехода исправлены.
- Возвращена исходная очистка ветки 4675. Добавленная ранее очистка дочернего указателя 4675–4676 теперь не нужна.
- C-мост принимает и возвращает 64-битные счётчики команд. Это устраняет переполнение при исследовании глубин 4–5. Обычная глубина 3 подтверждена отдельным сравнением старого и нового моста.
- Лимит одного запуска поиска увеличен с 300 миллионов до 3 миллиардов команд: восстановленный поиск ответов на шах может быть заметно дольше. Лимит означает защитную остановку, а не исторические часы и не выбор последнего найденного хода.

Описание доказательства и отвергнутых гипотез: `docs/V11_SEARCH_RU.md`. Данные нового исследования находятся в соседних каталогах `v12-*`; прежние эксперименты остаются в архиве v11.

## Командная строка и повторение сверки

```sh
python3 play.py --think --depth 3
python3 play.py --think --depth 5 --budget 12000000000 --moves e2e4 e7e5 b1c3 b8c6
python3 tests/search_regression.py
python3 tests/verify.py --plies 0
python3 tests/history_compare.py --depth 3 --out test-results/repeated-v11
```

Глубины 4–5 доступны в `--think` и API как исследовательские. Некоторые позиции на глубине 5 не завершаются даже за 12 миллиардов команд. Возвращается ошибка; готовый исторический ход не подставляется.

`tests/history_compare.py` использует полную историю PGN, сохраняет результат после каждого решения и проверяет отпечаток исходников при `--resume`. Ошибки и тайм-ауты имеют `match: null`, не выдаются за ответы. `--budget` задаёт лимит каждого вызова интерпретатора; при повторе с широким окном он применяется заново.

## Проверки и ограничения

Проверены 421 позиция генератора и 9322 применения хода, обе рокировки, частичные права, взятие на проходе, превращения со взятием за оба цвета, два мата в один ход и специальная регрессия обоих переходов в исправленном блоке. В отдельной самоигре сохранены 94 легальных полухода; 95-й проверен отдельно. Завершение полной самоигры не заявляется.

Формат М-20 допускает только превращения в ферзя и ограниченное число слотов однотипных фигур. История рокировки восстанавливается по полной записи; из произвольной FEN она может быть неизвестна, что отмечается в JSON. Состояние C-эмулятора общее для экземпляров внутри процесса: параллельные поиски выполняйте в отдельных процессах.

Точная матчeвая редакция рукописи и некоторые параметры форсированного поиска не установлены. Сохранены известные реконструированные особенности CPU, в частности Ω для команд 053/073. Это действующая исследовательская реконструкция, не побитово доказанная копия матчевой машины.
