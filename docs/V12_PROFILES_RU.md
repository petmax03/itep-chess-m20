# Профили поиска v12

По умолчанию сохранён профиль `v11`. Интерфейс доски, API состояния, результат поиска JSON и экспорт PGN указывают действующий профиль. При открытии сохранённой партии настройки берутся из текущей команды запуска; запись `search_profile` в game.json имеет информационное назначение.

| Профиль | 4344 | 4777 | 1661 | Предел ранга | Форсированная схема | Память |
|---|---|---:|---:|---:|---|---|
| v11 | напечатанный1057 | 0 | 3 | 14 | native | прежняя |
| v12-source | символический1054 | 0 | 3 | 16 | native | перенесены указатели и четыре массива линий |
| v12-narrow | напечатанный1057 | 0 | 3 | 14 | narrow | прежняя |

`v11` без переопределений сохраняет прежние машинные слова и поведение v11. `v12-source` и `v12-narrow` — исследовательские гипотезы, а не заявление о восстановлении точной матчевой настройки. При напечатанном4344 ячейка4777 фактически не читается на доступных рангах.

Новые параметры командной строки действуют и для доски, и для `--think`:

- `--profile v11`, `--profile v12-source` либо `--profile v12-narrow`.
- `--forced-scheme native` либо `--forced-scheme narrow`: штатный или узкий форсированный генератор.
- `--checks 0..4`: лимит шахов, ячейка4777 = n<<39.
- `--evaluations 1..5`: лимит оцениваний, ячейка1661 = n<<36.
- `--rank-cap 14` либо `--rank-cap 16`: абсолютный ранг. Значение16 всегда включает проверенный перенос пяти массивов;14 использует исходное размещение.
- `--source-4344`: адрес1054 по символической формуле.
- `--printed-4344`: адрес1057 из машинной колонки.

Примеры:

```sh
sh run.sh --profile v12-source
sh run.sh --profile v12-narrow
python3 play.py --think --profile v11 --depth 3
python3 play.py --think --profile v12-source --checks 2 --evaluations 3 --rank-cap 16 --source-4344
```

Python API: `Machine(profile="v12-source", checks=2, evaluations=3, rank_cap=16, source_4344=True).think(board, depth=3)`. Старое `Machine()` сохраняет профильv11. Параметр `forced_scheme="narrow"` доступен независимо от профиля. Узкий режим меняет только A1 команды4332 с3 на2; код4221 по-прежнему переключает генератор на режим6 при шахе. Глобальная ячейка3636 не перезаписывается извне.

Настройки применяются в `engine/search_profiles.py` после `BASE_PATCHES`. Перенос памяти находится в `engine/native_rank_capacity.py`; он проверяет исходные слова и свободные области перед изменениями. Исходный листинг и CPU не изменены. Ячейки5061/5062 намеренно не вынесены как параметры поиска: это внешний режим ввода/записи, а не глубина и не число шахов.

`lambda_final_1706` содержит низшие24 бита ячейки1706 после последнего родного поиска. `nodes` сохраняет прежний смысл: при `wide_window_retry` это сумма первого и повторного поиска. Для исторического сравнения финальногоλ используйте `lambda_final_1706` и отдельно учитывайте `search_mode`; сумма двух поисков не является одним историческим счётчиком.

`search_profile` в ответе содержит имя профиля, окончательные значения, список явных переопределений, машинные слова4332/4344/4777/1661 и тип размещения памяти. Одновременные поиски в одном процессе не поддерживаются из-за общего C-состояния; для параллельной матрицы нужны отдельные процессы.


Проверка конфигураций сохранена в `test-results/v12-profile-base-proof.json`: все4096 слов каждого из трёх профилей сравнены с соответствующей исследовательской базой; совпадение полное. Хеши листинга, CPU, определений CPU и C-моста совпадают с матричными запусками. Проверка не выполняет поисков; отдельная короткая CLI-проба v12-narrow из начальной позиции вернула e4, λ3673.
